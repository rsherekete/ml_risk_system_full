From first principles — 2 of 2

Abuse = Toxic behaviour ∩ money made in the next n days.

Being in C is a behaviour. It only becomes a cost when it makes money at our expense. So we intersect C with future profitability:
A = C  ∩  { account gains equity over the next n = 5 days }   (n configurable & optimised)

Why this is the right definition

  • Abuse is a weekly state — an account abusive this week can be harmless the next. So we evaluate it every window, not once for life.
  • We act only on A, never all of C — harmless "toxic-looking" flow stays in the B-book earning revenue. False positives are expensive too.
  • The benchmark is a perfect oracle that A-books an account exactly for its profitable toxic weeks — the natural 100% upper bound we measure against.

Why balance & deposits don't enter

A client could withdraw the gain at the end of day 5. Only money made after the qualifying behaviour is the adverse cost — so the measure is a clean equity delta, consistent across cent accounts and contract specs.

Core requirement #2 — the logic under the hood

Five steps, every one explainable to a first-year analyst.

1 · Observe

Every trade + tick, from all servers (sub-2s). Compute behavioural metrics: markout (adverse selection), hold-time, martingale rate, notional, overnight share.

→

2 · Classify

Transparent rules place each account-day in its Toxic/Arbitrage classes. Every flag traces to a metric and a threshold. No black box.

→

3 · Predict

An explainable model per class (random forest) turns today's behaviour into P(becomes Abuse within 5 days) — foresight, with feature importances.

→

4 · Act

The predicted class picks the optimal response: route to A-book, widen spread, restrict, or monitor — sized to the expected cost.

→

5 · Learn

Tomorrow's ground truth scores today's prediction. The models re-fit walk-forward with transfer learning — a closed feedback loop.

The intelligence is powerful because it is simple: a chain of measurable definitions, a transparent classifier, and a model whose every driver can be named. If it flags an account, we can always say exactly why.

The frontier — discovering abuse we haven't named yet

Turn the lens around: find the profit we can't yet explain.

  • Search for accounts that are profitable over the 5-day window and predictable in advance — yet fit no existing class.
  • These are candidate new abuse classes, surfaced automatically by mining every source: trades, ticks, funding, markout, exposure.
  • If the AI can explain the pattern → we name a new class and add it.
  • If it cannot yet → we can still act on the evidence (predictable adverse profitability) before the explanation matures, when the logic and the money justify it.

The framework doesn't just police the abuse we know. It is a discovery engine for the abuse we don't — the difference between reacting to last quarter's arbitrage and getting ahead of next quarter's.
