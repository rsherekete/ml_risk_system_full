Network allowlist

Checked before sign-in: a source outside these ranges gets 403 and never sees the login page. Loopback is always allowed. Leave the box empty for no restriction. This is a perimeter, not the access control — authentication is.

Currently {{ allowlist_count }} range{{ 's' if allowlist_count != 1 }} in effect, from the {{ allowlist_source }}{% if allowlist_by %}, last changed by {{ allowlist_by }}{% endif %}. You are connecting from {{ client_ip }}.

Comma-separated addresses or CIDR ranges. Use ranges for VPN users — a VPN hands out a different address per device and per session, so single addresses look right and admit almost nobody.

A saved list that would block your own address is refused unless you tick the box — locking yourself out of the machine you administer is the usual way this goes wrong. Blocked requests are logged as [ip-allowlist] blocked <ip>, so a teammate who cannot connect is diagnosed from the log rather than guessed at.

Sessions

A password change does not end sessions already signed in — that is handled per user above. Use this after a credential leak, when you want every cookie dead regardless of who holds it.

You will be signed out too, and land back on the login page.

Restart this instance

Changes to the Python code only take effect on a restart — templates reload by themselves, application code does not. Until a restart, the app runs new templates against old code, which is how a page can break in ways the files on disk do not explain.

The copy trader resumes on start. vantage.yaml carries mode: live and the kill switch is not persisted, so it comes back disengaged whatever it was before — check the copier once this returns. The restart is refused while a history refresh or a partition write is in flight, so it cannot truncate the warehouse.

Takes ~60–90s. This page will fail to load, then come back on its own — a bound port is not a ready app, so give the caches a moment.
